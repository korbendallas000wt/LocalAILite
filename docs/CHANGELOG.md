
# История изменений — LocalAILite

## [1.4.0] — 2026-08-09

### Добавлено
- **PathsManager (`core/paths_manager.py`)** — единый модуль управления путями (v2.0):
  - Единая точка доступа ко всем путям компонентов (Ollama, SDXL, output)
  - Ключи QSettings, дефолты, размеры (GB), человекочитаемые labels, критичность — в одном месте
  - `get_raw_paths()` — сырые значения для детектирования изменений (пустая строка = не указано)
  - `get_effective_paths()` — с fallback на дефолты (нормализация путей)
  - `set_path()` — единственный способ записи путей в Config
  - Валидация с уровнями: 0=формат, 1=существование, 2=функциональность
  - Источники моделей из `data/model_sources.json` (с fallback на дефолтные ссылки)
- **Реестр моделей v2.0 (`core/models_registry.py`)**:
  - Новый формат: `{"short_name": {"path": ..., "full_name": ..., "type": ...}}`
  - `KNOWN_MODELS` — статический маппинг известных моделей в читаемые имена (SDXL Base 1.0 вместо stable-diffusion-xl-base-1.0)
  - Поддержка типов: `hf_cache`, `file`, `folder` с иконками
  - Автоматическое `beautify_name()` для неизвестных моделей
  - Проверка актуальности по пути (пути должны быть внутри текущего `models_path`)
  - Использование PathsManager для получения эффективного пути (пустой путь → дефолт)
- **Инсталлятор (уровень 2)** — полная установка в `installer/cli.py`:
  - Шаг 5: `step_paths.py` — интерактивная настройка путей (Ollama бинарник/модели, SDXL venv/модели, output)
  - Шаг 6: `step_ollama.py` — скачивание и установка бинарника Ollama (~2.1 GB)
  - Шаг 7: `step_sdxl_env.py` — создание SDXL venv с torch/diffusers (~6 GB)
  - Шаг 8: `step_models.py` — скачивание моделей Ollama и SDXL (рекомендации советника)
  - Идемпотентность: все шаги пропускаются на уже установленной машине
- **Индикатор активной модели** в `ui/shared_bottom_bar.py`:
  - Строка ресурсов показывает модель при генерации: `㊘ Генерация Ollama · qwen2.5:3b`
  - Получение имени модели из ComboBox активного таба при захвате ресурса
- **Ссылки на источники моделей** в диалоге управления (из `data/model_sources.json`)

### Изменено
- **ComboBox моделей** в `ui/tabs/diffusers_settings_panel.py`:
  - `editable=False` — пользователь выбирает только из списка реестра (нельзя вводить текст)
  - Кнопка 🔄 обновления списка моделей из папки
  - Короткие читаемые имена (SDXL Base 1.0) вместо технических
- **Диалог управления моделями** в `ui/dialogs/diffusers_models_dialog.py`:
  - Полные имена с типами: `📦 SDXL Base 1.0 (HF cache: stabilityai/stable-diffusion-xl-base-1.0)`
  - Ссылки на источники моделей (HuggingFace, CivitAI)
- **Валидация путей** — переход с `on_text_changed` (на каждый символ) на `editingFinished` (Enter/потеря фокуса):
  - Убрана задержка ввода (валидация не блокирует UI)
  - Эмит `editingFinished` после выбора через диалог 📁 (валидация запускается сразу)
- **Переключение всего UI-слоя путей на PathsManager**:
  - `ui/dialogs/paths_dialog.py`, `ui/dialogs/settings/paths_settings_widget.py`
  - Детектирование изменений через `get_raw_paths()` (сравнение до/после)
  - Диалог «Пути изменены» → «Освобождение ресурсов» → перезагрузка

### Исправлено
- **Баг пустого реестра моделей** — пустой `{}` реестр теперь пересоздаётся (раньше считался актуальным)
- **Баг старых путей в реестре** — пути должны находиться внутри текущего `models_path` (при смене папки реестр пересоздаётся)
- **Баг валидации путей** — «галочка то есть, то нет» устранён (валидация только по Enter/фокусу, не на каждый символ)
- **Баг `step_ollama.py`** — контракт «путь к файлу бинарника» (а не к папке): корректное определение типа пути
- **Баг `step_models.py`** — сканирование папки `manifests/` напрямую, без запущенного сервера Ollama (раньше `ollama list` требовал сервер)
- **Баг генерации с неполной HF cache моделью** — диагностика и перемещение полной копии в корень папки моделей
- **Баг индикатора ресурсов** — `resource_acquired` теперь передаёт имя модели в `SharedBottomBar.set_mode()`

### Архитектура
- **PathsManager как единый источник правды** — все компоненты (CLI-инсталлятор, UI-визард, настройки приложения) читают/пишут пути только через PathsManager. Никаких захардкоженных дефолтов в других местах.
- **Двухуровневая валидация путей**:
  - Уровень 0 (формат): папка существует и доступна
  - Уровень 1 (содержимое): реестр не пуст — есть хотя бы одна модель
- **Реестр v2.0 с типами** — поддержка трёх форматов моделей (HF cache, single-file, распакованная папка) с автоматическим определением
- **Инсталлятор уровня 2** — сквозная установка от диагностики до моделей, идемпотентная, с интерактивными вопросами
- **Индикатор модели в строке ресурсов** — пользователь всегда видит, какая модель генерирует, без отдельного виджета



## [1.3.0] — 2026-08-06
### Добавлено
- **Инсталлятор (уровень 1 — бутстрап)** — новый модуль `installer/`:
  - `detector.py` — диагностика ОС, CPU (sse4_2, popcnt, avx, avx2, fma), RAM, GPU, Python, диск. Методы `can_use_pip_pyqt6()`, `detect_system_pyqt6()` для определения стратегии установки Qt
  - `requirements.py` — пороги ресурсов (RAM, CPU, диск)
  - `advisor.py` — честные вердикты, что потянет машина (Python/Ollama/SDXL), подбор моделей под железо
  - `steps/base.py` — контракт идемпотентного шага установки (`InstallStep`, `StepStatus`)
  - `steps/step_config.py` — создание служебной структуры `data/` (5 папок: history, init_images, logs, pids, previews)
  - `steps/step_env.py` — создание venv с **гибридной стратегией PyQt6**: pip на современном CPU (sse4_2+popcnt), системный из pacman на старом (без sse4_2/popcnt) через `--system-site-packages`
  - `cli.py` — точка входа бутстрапа (`python3 installer/cli.py`), последовательно прогоняет шаги с прогрессом
### Изменено
- `utils/config.py` — пути бинарника/библиотек Ollama настраиваемые через QSettings (`ollama/binary_path`, `ollama/lib_path`), убран `get_ollama_data_dir()`
- `core/ollama_manager.py` — убрана неиспользуемая переменная `OLLAMA_DATA_DIR` (Ollama её игнорировал, данные шли в `~/.ollama`)
- `data/` — ревизия структуры: удалены неиспользуемые папки `cache/`, `checkpoints/`, `ollama/`
### Архитектура
- **Принцип «не навязываем, но помогаем максимально»** — детектор честно говорит, что потянет машина, и предлагает лучший путь установки
- **Идемпотентность** — повторный запуск инсталлера пропускает уже установленное
- **Гибридная стратегия PyQt6** — обход несовместимости pip-PyQt6 на старых CPU (без sse4_2/popcnt) через системный пакет из pacman
- Проверено на Xeon E5450 без AVX2/SSE4.2 — самом сложном тестовом железе



## [1.2.1] — 2026-08-03

### Добавлено
- **Точечная выгрузка контекста** — `get_context.sh`: скрипт выборочной склейки файлов для LLM (вместо полного `full_context.py`, который искажался при передаче больших объёмов)
- **Утилита сравнения изображений** — `scripts/compare_images.py`: попиксельное сравнение PNG через numpy (корректнее побайтового `cmp`, не реагирует на метаданные)
- **Защита от перезаписи финального изображения** — если `sdxl_{seed}.png` уже существует, результат сохраняется как `sdxl_{seed}_1.png`, `sdxl_{seed}_2.png` и т.д.

### Изменено
- **Проверка RAM** (`check_ram_available`) — считает реальную свободную память системы через `psutil.virtual_memory()`, а не абстрактный «лимит минус GUI-процесс». Учитывает память всех процессов и запас до пользовательского лимита (с резервом 10%)
- **Оценка потребления SDXL** (`estimate_diffusers_ram`) — реалистичные значения: 9 GB для 512×512, ~11 GB для 1024×1024 (ранее заниженные 6–8 GB)

### Исправлено
- **Точный resume из чекпоинтов** — два критических бага в `scripts/generate_diffusers.py`:
  - Срез `timesteps[start_step:]` вместо передачи полного списка (диффузерс больше не гонит все шаги заново)
  - Компенсация `init_noise_sigma` (предварительное деление латентов), чтобы конвейер не масштабировал их повторно при передаче из чекпоинта
  - Результат: картинка после resume идентична непрерывной генерации (~0.2% пикселей с отличием на 1, это float-округление)
- **CleanupDialog** — добавлены недостающие методы `ResourceMonitor.read_pid_file` / `is_process_alive` / `kill_process_by_pid` (шаг 1 очистки больше не падает с `AttributeError`)
- **Утечка ресурса** — `release_resource()` вызывается при раннем выходе из диалога сохранения истории (`diffusers_tab.py`)
- **Гонка при остановке** — `worker.stop()` под защитой `if self.worker` (`diffusers_tab.py`)
- **Коллизия имён табов** — состояние Visual editor больше не затирает Diffusers в QSettings (`main_window.py`)

### Архитектура
- **Контекст для LLM** — переход от монолитного `full_context.py` к точечной выгрузке `get_context.sh` (меньше объём → нет искажений при передаче)
- **Проверка RAM** — честный контроль по реальной памяти, защита от ухода в своп

## [1.2.0] — 2026-07-14

### Добавлено
- **Оптимизация CPU для VAE** — в `scripts/generate_diffusers.py` добавлены `torch.set_num_threads(cpu_count)` и `pipe.enable_vae_tiling()` для ускорения декодирования
- **Цветовая подсветка статусов** — серый (логи), золотой (статусы), оранжевый (предупреждения), красный (ошибки), зелёный (успех)
- **Единая кнопка действия** — три состояния: `▶ Генерация` / `⏹ Остановить` / `Завершение...` (неактивно)

### Изменено
- **Откат VAE Manager** — удалены `core/vae_manager.py` и `scripts/vae_decoder_daemon.py`. VAE теперь работает внутри процесса генерации (монолитно), убран из списка арендаторов ресурсов
- **Упрощён callback** — в `scripts/generate_diffusers.py` на каждом шаге сохраняется только `.pt` + `.json`, без VAE decode (ускорение генерации)
- **Изоляция статусов** — каждая вкладка ведёт свой `_bar_state`, MainWindow не пишет в SharedBottomBar напрямую
- **Переключение вкладок** — `unload()` больше не останавливает генерацию, табы переключаются свободно

### Исправлено
- **CleanupDialog** — восстановлен в `closeEvent`, работает корректно (убран мёртвый код из `_on_resource_released`)
- **ResourceMonitor** — интегрирован в `DiffusersWorker` и `OllamaManager` (RAM check + CPU affinity + priority)
- **Кнопка «Стоп»** — корректно возвращается в «Запустить» после завершения генерации
- **Статусная строка** — убрано накопление сообщений через `·`, каждый статус заменяет предыдущий

### Архитектура
- **VAE в отдельном процессе не нужен** — борьба за ресурсы (CPU affinity, GIL) съедает выигрыш, монолитное декодирование быстрее
- **2 арендатора ресурсов** — Ollama и Diffusers (VAE убран)
- **Свободное переключение вкладок** — генерация не прерывается при уходе с таба
- **Изоляция табов** — каждый таб сам отвечает за свой статус, включая системные сообщения

## [1.1.0] — 2026-07-11

### Добавлено
- **core/vae_manager.py v1.1.0**: Менеджер VAE Decoder как отдельный арендатор ресурсов. QProcess-обёртка для vae_decoder_daemon.py, интеграция с ResourceManager (acquire/release), применение CPU affinity и nice-приоритета.
- **scripts/vae_decoder_daemon.py v1.1.0**: Daemon для декодирования latents в PNG. Поддержка параметра --single_file для декодирования конкретного шага по запросу UI. Watchdog-режим: отслеживает появление новых .pt файлов в history_dir.

### Изменено
- **core/diffusers_worker.py**: Интеграция ResourceMonitor — проверка RAM перед запуском, применение лимитов CPU (OMP_NUM_THREADS, cpu_affinity, nice-приоритет). Адаптация под diffusers 0.39+ (callback_on_step_end вместо устаревшего callback). Упрощение сохранения чекпоинтов: синхронная запись вместо daemon-потоков (~0.1 сек на фоне 500 сек шага).
- **core/ollama_manager.py**: Интеграция ResourceMonitor — проверка RAM перед запуском, применение CPU affinity и nice-приоритета.
- **core/resource_manager.py**: Теперь управляет тремя арендаторами: Ollama, Diffusers, VAE Decoder.
- **scripts/generate_diffusers.py**: Адаптация под diffusers 0.39+ (callback_on_step_end). Синхронное сохранение чекпоинтов на каждом шаге.
- **ui/shared_bottom_bar.py**: Исправлен таймер — запускается один раз при старте, не сбрасывается на каждом шаге.
- **ui/main_window.py**: Восстановлен CleanupDialog в closeEvent. Убран мёртвый код из _on_resource_released.

### Исправлено
- **Resume из архивных чекпоинтов**: Генерация больше не зависает на одной картинке. Корректно передаются latents, timesteps и num_inference_steps=remaining_steps в diffusers 0.39+.
- **Таймер SharedBottomBar**: Больше не сбрасывается на каждом шаге генерации.
- **CleanupDialog**: Корректно вызывается в closeEvent. Убран NameError из _on_resource_released.
- **Отображение дат в UI**: Исправлен формат (2026.07.05 14:30:45 вместо кривого).
- **Скрытые падения**: Устранены NameError, NoneType.pop в различных сценариях.

### Архитектура
- **VAE Decoder вынесен в отдельный процесс**: Попытки делать VAE decode в daemon-потоке внутри процесса генерации провалились из-за GIL и конфликта CPU affinity. VAEManager — полноценный арендатор ресурсов (как Ollama/Diffusers).
- **Синхронные чекпоинты**: Убран оверхед с daemon-потоками. Операция занимает ~0.1 сек на фоне 500 сек шага.
- **Контроль ресурсов**: Приложение жёстко ограничено настройками пользователя (RAM/CPU), не мешает системе.

- **Модульная архитектура**: SRP, сигнальная маршрутизация, изолированные потоки (QThread для сети, QProcess для тяжёлых задач).
- **Чекпоинты генерации**: Сохранение/восстановление прогресса (latents + scheduler + generator), архивация с timestamp.
- **Управление ресурсами**: Мониторинг RAM/CPU, лимиты, выгрузка неактивных модулей при переключении табов.
- **Ollama Manager**: Автоматический запуск/остановка сервера, обработка конфликтов портов, логирование.
- **SharedBottomBar**: Единая нижняя панель для обоих табов (промпт, прогресс, таймер, RAM/CPU).
- **CleanupDialog**: Корректное освобождение ресурсов при закрытии (5 шагов).
- **Markdown-парсер**: Подсветка кода, копирование блоков, адаптация под системную тему KDE.
- **Нативная тема KDE**: Без артефактов, адаптивный UI.

### Изменено
- **Архитектура**: Полное разделение UI и бизнес-логики. UI-модули только отрисовка и маршрутизация сигналов, вся логика в core/.
- **Потоки данных**: Чат через OllamaClient (QThread), генерация через DiffusersWorker (QProcess), изоляция от UI-потока.
- **Конфигурация**: Единый QSettings-обёртка (utils/config.py) для всех настроек.
- **Чекпоинты**: Атомарная запись JSON + PT, архивация с timestamp для истории.

### Исправлено
- Устранены UI-фризы за счёт выноса сетевых запросов в QThread.
- Изоляция тяжёлых задач (генерация) в QProcess для возможности остановки и логирования.
- Корректная очистка ресурсов при закрытии через CleanupDialog.
- Адаптация под нативную тему KDE без артефактов.
