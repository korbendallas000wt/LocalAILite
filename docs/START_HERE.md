## 🚀 Быстрый старт

### 1. Установка зависимостей

    # Создаём venv
    python3 -m venv venv
    source venv/bin/activate

    # Устанавливаем зависимости
    pip install PyQt6 requests psutil

### 2. Запуск приложения

    python main.py

### 3. Структура проекта

- **`docs/`** — документация (этот файл, `STRUCTURE.md`, `CHANGELOG.md`)
- **`core/`** — ядро (логика без UI)
- **`ui/`** — PyQt6 интерфейс
- **`installer/`** — инсталлятор (идемпотентный)
- **`data/`** — рабочие данные (в `.gitignore`)

## 📊 Текущее состояние (2026-08-22)

### Что сделано

#### Версия 1.7.0 (2026-08-26)
✅ **Ветвление диалога** — полноценная система альтернатив для LLM-чата:
- Кнопка «✏ Правка» под сообщением пользователя запускает режим правки: обрезает чат до точки ветвления, возвращает текст в промпт
- Кнопка «↶ Отменить» в режиме правки возвращает хвост без создания нового чата
- При отправке правки создаётся новый чат-ветка (`chat_N.json` в папке диалога)
- Поле `variants` в сообщениях хранит номера чатов-альтернатив — точная навигация без перебора
- Кнопки навигации под сообщением показывают варианты, если их больше одного
- Кнопка «🗑 Удалить чат» в панели управления удаляет текущий файл и переключается на соседний
- Автосохранение после каждого сообщения и кнопка «💾 Сохранить» для экспорта в JSON/TXT
✅ **Чистка мёртвого кода (−334 строки):**
- Удалены паспорта сообщений (`id`/`uuid`) — сообщения идентифицируются стабильным `user_msg_index`
- Удалён метод `find_alternatives` (паспортная навигация) из `chat_versions.py`
- Удалён файл `core/branch_cache.py` целиком (кэш веток отброшенной модели)
- Удалены мёртвые методы из `ollama_tab.py` (`_on_switch_branch_requested` и др.)
- Упрощён `chat_exporter.py` (убрана логика создания веток)
- Кнопка ветвления переименована в «✏ Правка» (устранена тёзка с режимом «Изменить» в настройках)
- Режим «Изменить» больше не создаёт ветки — просто сохраняет чат
✅ **Концептуальное решение навигации:** ветки живут в своей иерархии, правки в одной ветке не «протекают» в другие — это честное и корректное поведение, а не баг

#### Версия 1.6.0 (2026-08-22)
- ✅ **Сохранение и загрузка чатов** — экспорт в JSON (для машины) и TXT (для человека)
- ✅ **Режимы работы чата** — Новый / Продолжить (заблокированные настройки) / Изменить (свободные настройки)
- ✅ **Панель управления чатом** — 4 кнопки: Новый, Отменить, Файл, Сохранить
- ✅ **Автоназвание чатов через LLM** — генерация заголовка из контекста
- ✅ **Append-only рендеринг чата** — устранены O(N²) тормоза на слабых машинах
- ✅ **Live-статусбар** — плавный вывод токенов (throttling 10 Гц)
- ✅ **Таблицы и вложенные списки** в markdown-рендеринге
- ✅ **Модуль обновлений** (релиз 1.5.0) — проверка версий, скачивание, установка
- ✅ **Кросс-дистрибутивность** — 5 дистрибутивов (Manjaro, Fedora, Ubuntu, openSUSE, Void)

### Что осталось (приоритетные задачи)

1. **Восстановление UI при загрузке чата**
   - В продолженных чатах не отображается строка системных сведений и кнопки копирования ответа
   - Нужно убедиться, что `chat_widget.load_chat()` корректно вызывает `append_assistant_message` со `stats`

2. **Логика сохранения изменённого чата**
   - При изменении загруженного чата и его сохранении — предлагать "Сохранить как новый" (чтобы не перезаписывать оригинал) или сохранять под тем же именем с суффиксом
   - Вопрос для обсуждения с пользователем

3. **Загрузка файлов**

4. **Ollama Image Gen (Express-режим)**
   - Интеграция нативной генерации изображений через Ollama как лёгкой альтернативы Diffusers
   - Переключатель режимов (Express/Pro) в DiffusersTab
   - *Статус: отложено до официального выхода Linux-поддержки в Ollama*

5. **Быстрый перевод промптов**
   - Использование лёгкой LLM (1.5B) для мгновенного перевода русских визуальных промптов в оптимизированный английский формат для CLIP
   - Кнопка "🌐 Перевести промпт" в DiffusersTab
   - Кнопка `📎 Файл` в панели управления чатом сейчас заглушка

## 🔧 Разработка

### Git-воркфлоу

- **`main`** — стабильные релизы (зеркалится в `Repo/`)
- **`dev`** — активная разработка

### Коммиты

Формат: `feat: ...`, `fix: ...`, `refactor: ...`, `docs: ...`, `chore: ...`

Примеры:

    git commit -m "feat(chat): сохранение/загрузка чатов (JSON/TXT)"
    git commit -m "fix(ui): фикс улетания скролла при копировании"
    git commit -m "docs: обновление START_HERE.md для релиза 1.6.0"

### Тестирование

Перед коммитом:

1. Проверить синтаксис всех изменённых файлов:

    python3 -m py_compile <file>.py

2. Запустить приложение и протестировать изменённый функционал
3. Обновить `CHANGELOG.md` (если есть пользовательские изменения)
4. Обновить `STRUCTURE.md` (если добавлены/удалены модули)
