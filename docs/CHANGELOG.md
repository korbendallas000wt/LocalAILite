## [1.8.1] — 2026-09-03

### Добавлено
- **Подкраска фона прогрессбара токенов** (`ui/shared_bottom_bar.py`): через `QPalette.ColorRole.Window` (не ломает нативный стиль KDE Breeze). Три уровня: норма (≤70%) — нативный вид; внимание (70-90%) — оранжевый фон `#f0ad4e`; критично (≥90%) — красный фон `#d9534f`. Применяется только в Ollama-вкладке (`colorize=True`), на других табах прогрессбар нативный. Закрыта задача из Backlog релиза 1.8.0.
- **Меню «Модели» — прямое действие**: убрано подменю «Менеджер моделей...», пункт «Модели» сразу открывает Менеджер (как «Настройки»).

### Изменено
- **Полный редизайн Менеджера моделей** (`ui/dialogs/model_manager_dialog.py`):
  - Три блока в QGroupBox с рамками: «Список моделей», «Статус загрузки», «Информация о модели»
  - Кнопка «Действие» — три состояния: ⬇ Загрузить → ✕ Отменить (во время загрузки) → 🗑 Удалить (после установки)
  - Левая кнопка: 🔍 Проверить (установлена) / ❔ Вердикт (не установлена) — вердикт доступен ДО скачивания
  - Вердикт по УСТАНОВЛЕННОЙ RAM (psutil.total) — стабильно, не прыгает как доступная
  - Таблица: номер строки, центрированные заголовки, отключённое выделение строк, разделители, пропорциональные ширины колонок
  - Информационное поле: две колонки (метаданные + описание), без вердиктов и прокрутки
  - Статус загрузки: две строки (статусбар + чекбокс / прогрессбар во всю ширину)
  - Все QMessageBox через явный инстанс с `DontUseNativeDialog` (расширение KDE-фикса)
- **Консолидация управления моделями** (сессия 4):
  - `core/model_lifecycle.py` v1.0.0 — управление жизненным циклом: удаление (ollama rm, rmtree папки hf_cache), проверка целостности через `model_validator.py`, интеграция с `resource_manager`
  - `core/models_registry.py` — метод `remove_model_from_registry(config, full_name)`
  - Удаление `diffusers_models_dialog.py` (дубль из настроек)

### Исправлено
- **Валидация Diffusers-моделей** (`core/model_lifecycle.py`): для `hf_cache` путь из реестра ведёт на `snapshots/{hash}`, а валидатор искал `blobs/` в корне. Добавлен подъём от `snapshots/{hash}` до корня `models--*` в `validate_installed_model`.
- **Краш вердикта на KDE** (`ui/dialogs/model_manager_dialog.py`): segfault в деструкторе `QMessageBox` при попытке скрыть нативный диалог. Замена статических методов на явное создание `QMessageBox(self)` с `DontUseNativeDialog`.
- **Таймер после ошибки** (`ui/tabs/diffusers_tab.py`): в `_on_error` не останавливался таймер. Добавлен `self._generation_timer.stop()` первым действием.
- **Сброс подписи кнопки** (`ui/main_window.py`): при занятом ресурсе переключение на чужой таб сбрасывало кнопку в «Генерация». В `_on_tab_state_changed` добавлена проверка владельца ресурса.
- **Пустая папка истории при отмене** (`ui/dialogs/history_save_dialog.py`): закрытие диалога крестиком или Esc не эмитило сигнал — папка оставалась на диске. Добавлен `reject()`: эмитит `delete_history`, папка удаляется.
- **Инфо-поле сбрасывается при переключении вкладок** (`ui/dialogs/model_manager_dialog.py`): фикс бага, когда поле информации очищалось при смене таба.
- **Прогрессбар скачивания Diffusers-моделей** (`core/model_downloader.py`): `snapshot_download` не даёт прогресс в stdout → мониторинг размера папки модели (каждые 2с, `X.X / Y.Y GB`).

### Удалено
- Мёртвые файлы: `core/chat_exporter.py` (заменён функционалом в `ollama_tab.py`), `PHILOSOPHY.md` в корне (переехал в `docs/`), `docs/START_HERE.md` (больше не используется).

### Архитектура
- **SRP для моделей**: скачивание (`model_downloader.py`) ≠ удаление/проверка (`model_lifecycle.py`) — разделение ответственности.
- **Вердикт по установленной RAM**: стабильные рекомендации (не прыгают от загрузки системы).
- **Нативный стиль KDE**: отказ от QSS-подкраски прогрессбара (ломает объёмную оболочку) в пользу фонового цвета через палитру (`QPalette.ColorRole.Window`).


## [1.8.0] — 2026-08-31

### Добавлено
- **Счётчик контекста** — прогрессбар токенов в нижней панели (использовано / лимит модели). Обновляется при смене модели, изменении промпта, добавлении сообщений.
- **Вложения в чат с карточкой** — `📄 имя · размер · ✕` в сообщении: клик по имени открывает файл в системе (`xdg-open`), клик по ✕ удаляет вложение из промпта. При отправке вложения впечены в запрос к модели.
- **Менеджер моделей** — меню «Модели» → «Менеджер моделей...»: список доступных моделей (Ollama и Diffusers), фильтр по железу через вердикты `advisor.py`, вердикт по ОЗУ в панели деталей, скачивание с прогрессом и отменой. Дефолтная витрина (3 модели в секции) расширяется через `data/shared/registry/available_models.json` без правки кода.
- **FolderDialog** — обёртка над `QFileDialog` с двумя режимами: `navigate` (стандартная навигация) и `select` (вход в папку = выбор). Используется для выбора папки чатов без навигации внутрь.
- **Скриншоты в README** — 4 кадра: чат с вложением, генерация SDXL, Менеджер моделей, инсталлятор.

### Изменено
- `core/updater.py` → **v2.1**: проверка версий теперь асинхронная через `QNetworkAccessManager` (без блокирующего `urlopen`). `UpdateWorker(QThread)` сохранён только для скачивания/установки архива.
- `core/models_registry.py` → **v1.5.0**: добавлены методы `list_available_models(config)` (дефолт в коде + override из `available_models.json`) и `list_installed_ollama_models(config)` (сканирование `manifests/` без сервера).
- `ui/main_window.py` → **v1.3.0**: добавлено меню «Модели» между «Файл» и «Инструменты».
- Блокировка кликов по карточкам вложений во время генерации (защита от краша Wayland при модальных окнах).

### Исправлено
- **Краш `QThread: Destroyed while thread is still running`** при быстром закрытии настроек. Корень: `_VersionCheckWorker` с блокирующим `urlopen(timeout=10)` не успевал завершиться за 3 секунды `wait()`. Решение — переход на `QNetworkAccessManager` (Qt сам отменяет запросы при уничтожении объекта).
- **Ложный успех скачивания fp16-моделей** (например, Juggernaut XL v9): жёсткие `allow_patterns` не ловили файлы `*.fp16.safetensors`. Фикс: чтение состава репозитория через `list_repo_files` + динамический выбор весов (предпочтение fp16), явная ошибка если весов нет.
- **Прогрессбар скачивания висел на 5%**: парсер разбивал вывод только по переводам строки, а прогресс пишется через возврат каретки. Фикс: разбивка по обоим символам.
- **Загрузка fp16-моделей падала** (`no file named diffusion_pytorch_model.safetensors`): `from_pretrained` без `variant` не видит fp16-весов. Фикс в `scripts/generate_diffusers.py`: детекция варианта по фактическим файлам + передача `variant="fp16"`.
- **Диалог прыгал на вкладку Ollama после скачивания** модели: пересоздание вкладок сбрасывало индекс. Фикс: сохранение и восстановление текущей вкладки.

### Важно
- **Временно отключено перед релизом:**
  - Подсветка прогрессбара токенов (зелёный/оранжевый/красный) — ломала форму полосы. Вернётся после подбора системных цветов Qt.
  - Промежуточные превью по шагам генерации — сильно тормозят процесс. Вернутся после подбора лёгкого декодера.
- **Архитектурное решение** модуля загрузки: дефолтный список моделей захардкожен в коде (константа `AVAILABLE_MODELS_DEFAULTS`), файл `available_models.json` работает только как override для кастомизации. Работает из коробки без файла.

## [1.6.0] — 2026-08-22

### Добавлено
- **Сохранение и загрузка чатов**:
  - `core/chat_exporter.py` — экспорт чатов в два формата: JSON (для машины: точное воспроизведение, настройки, статистика токенов) и TXT (для человека: читаемый markdown с разделителями `== Вы ==` / `== Модель ==`)
  - Генерация имён файлов: дата + санитизированный заголовок (с fallback на timestamp при пустом названии)
  - Автогенерация заголовка через LLM (опционально, через настройки) — модель получает первые 6 сообщений и придумывает 3-словный заголовок
  - Кнопка `📂` в `settings_panel.py` для выбора сохранённого чата через файловый диалог
- **Режимы работы чата** (три радиокнопки в правой панели):
  - **Новый** — чистый лист, все настройки активны, поле выбора чата заблокировано
  - **Продолжить** — загрузка чата из JSON, **настройки заблокированы** (чтобы сохранить оригинальный контекст LLM)
  - **Изменить** — загрузка чата из JSON, **все настройки активны** (для экспериментов: смена модели, температуры, system prompt)
- **Панель управления чатом** (`ui/chat_control_panel.py`) — 4 кнопки:
  - `+ Новый чат` — очистка истории с защитным вопросом "Сохранить перед очисткой?"
  - `↶ Отменить` — возврат последнего промпта в поле ввода (аналог Undo)
  - `📎 Файл` — заглушка для будущей загрузки файлов
  - `💾 Сохранить` — экспорт чата в JSON/TXT
- **Вкладка "Чат" в настройках** (`ui/dialogs/settings/chat_settings_widget.py`):
  - Форматы сохранения: JSON (для RAG и поиска) и/или TXT (для архива)
  - Автопрокрутка к новому сообщению
  - Автоназвание через LLM
  - Выбор папки для сохранённых чатов (`data/ollama/chats/`)

### Изменено
- **`ui/chat_widget.py` v1.2.0 — Append-only рендеринг**:
  - Устранены O(N²) тормоза на слабых машинах: вместо перерисовки всего HTML на каждое сообщение, `ChatWidget` теперь только добавляет готовые HTML-блоки
  - История хранится как список пар `(role, html)` и рендерится через `_rerender()` с сохранением позиции скролла
  - Добавлен метод `load_chat(messages)` для загрузки истории из JSON
- **`ui/settings_panel.py` v1.2.0 — режимы работы**:
  - Убраны кнопки "Очистить чат" и "Отправить" (дублировали функционал панели управления)
  - Добавлены радиокнопки режимов + поле выбора чата + кнопка сброса настроек к дефолту
  - Метод `_update_ui_state()` управляет блокировкой виджетов в зависимости от режима
  - Метод `apply_settings_from_chat()` применяет настройки из загруженного чата

  - Два глобальных состояния: **Свободное** (режим можно менять) и **Зафиксированное** (режим заблокирован)
  - Фиксация происходит при: первой отправке промпта в режиме "Новый" ИЛИ загрузке чата в режимах "Продолжить"/"Изменить"
  - Разблокировка происходит при: сохранении чата (`_save_chat()`) ИЛИ очистке (`_clear_chat_internal()`)

  - Поддержка таблиц GFM (GitHub Flavored Markdown) с выравниванием колонок
  - Вложенные списки (до 3 уровней вложенности) с разными маркерами (`-`, `*`, `+`)

### Исправлено
- **Фикс бага очистки перед сохранением** (`ollama_tab.py`):
  - Раньше: кнопка "+ Новый чат" очищала чат мгновенно, и асинхронное сохранение (с генерацией заголовка через LLM) сохраняло пустой чат
  - Теперь: флаг `_pending_clear_after_save` гарантирует, что очистка произойдёт только после успешного сохранения
  - Если пользователь отменил ввод названия в диалоге — флаг сбрасывается
- **Plain text в промпте** (`shared_bottom_bar.py`):
  - Вставка из буфера обмена теперь автоматически преобразуется в plain text (устраняет форматирование из браузера/документов)
  - Используется `QClipboard.text()` вместо `QClipboard.mimeData().text()`
- **Фикс улетания скролла при копировании** (`chat_widget.py`):
  - Копирование кода или ответа больше не вызывает прыжок скролла вверх
  - Позиция скролла сохраняется перед операцией и восстанавливается через `QTimer.singleShot(0)`
- **Ожидание TIME_WAIT для Ollama** (`ollama_manager.py`):
  - После остановки сервера добавлена пауза 30 секунд перед повторным запуском (защита от ошибки "порт занят")
  - Если порт не освободился за 30 сек — принудительный перезапуск через `kill_existing_and_start()`
- **Ручная очистка не убивает сервер** (`cleanup_dialog.py`):
  - При ручном вызове диалога очистки (через меню "Инструменты") Ollama-сервер не останавливается (только выгружает модели)
  - При закрытии приложения — сервер останавливается корректно

### Архитектура
- **Append-only рендеринг**: `ChatWidget` только добавляет блоки, никогда не перерисовывает весь HTML — устранены фризы на слабых машинах при длинных диалогах
- **Состояния таба**: два глобальных состояния (Свободное/Зафиксированное) вместо множества флагов — упрощена логика переходов
- **Блокировка настроек в режиме "Продолжить"**: чтобы сохранить оригинальный контекст LLM, настройки (модель, температура, system prompt) блокируются при загрузке чата — пользователь не может случайно их изменить и сломать логику диалога
- **Защита от потери данных**: кнопка "+ Новый чат" с несохранённым чатом всегда спрашивает "Сохранить перед очисткой?" — три варианта: Да (сохранить + очистить), Нет (очистить), Отмена (ничего не делать)
- **Асинхронная генерация заголовка**: запрос к LLM для генерации названия чата происходит в фоне (отдельный `OllamaClient`), не блокирует UI

### Проверено
- Сохранение/загрузка чата: JSON и TXT создаются в `data/ollama/chats/`, структура корректна
- Режимы работы: переключение между "Новый"/"Продолжить"/"Изменить" работает, блокировки применяются
- Автоназвание: LLM генерирует заголовок, диалог показывает предзаполненное значение
- Кнопка "+ Новый чат": защитный вопрос появляется при наличии сообщений, сохранение работает корректно
- Append-only рендеринг: длинные диалоги (100+ сообщений) не вызывают фризов
- Таблицы и вложенные списки: рендерятся корректно в `ChatWidget`
