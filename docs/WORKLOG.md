## Найденные баги

### Fedora 44 (dnf)

#### 1. UnicodeDecodeError при установке системного PyQt6
**Шаг:** 3 (step_env.py)  
**Симптом:** `UnicodeDecodeError: 'utf-8' codec can't decode byte 0xd0`  
**Корень:** `subprocess.run()` использует `text=True` с `locale.getpreferredencoding()` → cp1251 на Fedora, но вывод dnf в UTF-8  
**Фикс:** `encoding='utf-8', errors='replace'` в `step_env.py:112`  
**Статус:** ✅ Исправлено в коммите `0d65022`

#### 2. Ollama tarball изменён на .tar.zst
**Шаг:** 6 (step_ollama.py)  
**Симптом:** `HTTP 404` при скачивании `ollama-linux-amd64.tgz`  
**Корень:** Ollama релиз v0.15+ изменил формат архива с `.tgz` на `.tar.zst`  
**Фикс:** 
- URL обновлён на `ollama-linux-amd64.tar.zst`
- Команда распаковки: `tar -xf archive.tar.zst` (автоопределение zstd)
- Проверка размера файла перед распаковкой (защита от 404 HTML)

**Статус:** ✅ Исправлено в коммите `0d65022`

#### 3. Python 3.14 несовместим с torch/diffusers
**Шаг:** 7 (step_sdxl_env.py)  
**Симптом:** torch/diffusers не импортируются на Python 3.14  
**Корень:** PyTorch ещё не поддерживает Python 3.14 (актуально на 2026-08)  
**Фикс:** 
- Метод `_ensure_compatible_python()` — автоустановка Python 3.12 через пакетный менеджер
- Маппинг пакетов: `PYTHON_312_PACKAGES = {"dnf": "python3.12", "pacman": "python312", ...}`
- Предложение установки с sudo

**Статус:** ✅ Исправлено в коммите `0d65022`

#### 4. numpy конфликт с torch в SDXL venv

Шаг: 7 (step_sdxl_env.py)

## Технические заметки

### Гибридная стратегия PyQt6

**Проблема:** pip-PyQt6 не работает на старом CPU (Xeon E5450 без SSE4.2/AVX)  
**Решение:** Использовать системный PyQt6 из пакетного менеджера  
**Реализация:**
- `step_env.py` проверяет CPU flags через `detector.detect_cpu()`
- Если нет SSE4.2/AVX → создаёт venv с `--system-site-packages`
- Устанавливает системный PyQt6 через `sudo pacman -S python-pyqt6` (или apt/dnf/zypper)
- venv наследует системные пакеты

**Работает на:**
- ✅ Manjaro (Xeon E5450)
- ✅ Fedora 44 (Xeon E5450)
- ⏳ openSUSE (не тестировалось)

### Стратегия установки Python 3.12

**Проблема:** Fedora 44 по умолчанию ставит Python 3.14, который несовместим с torch  
**Решение:** Автоустановка Python 3.12 через пакетный менеджер  
**Реализация:**
- `step_sdxl_env.py` метод `_ensure_compatible_python()`
- Определяет пакетный менеджер через `detector.detect_os()`
- Маппинг пакетов:
  ```python
  PYTHON_312_PACKAGES = {
      "pacman": "python312",  # Manjaro (AUR)
      "dnf": "python3.12",     # Fedora
      "apt": "python3.12",     # Ubuntu/Debian
      "zypper": "python312",   # openSUSE
      ...
  }
  ```
- Предлагает установку с sudo
- После установки перезапускает детектор для проверки

**Работает на:**
- ✅ Fedora 44 (dnf)
- ⏳ openSUSE (не тестировалось)
- ⏳ Ubuntu (не тестировалось)

### SELinux на Fedora

**Проблема:** Fedora по умолчанию включает SELinux Enforcing, который блокирует запуск Ollama  
**Решение:** Применить `chcon -t bin_t` к бинарнику Ollama  
**Реализация:**
- `step_ollama.py` метод `_apply_selinux_context()`
- Проверяет наличие `getenforce`
- Если SELinux Enforcing → предлагает `chcon -t bin_t` с sudo
- Применяет контекст только после разрешения пользователя

**Работает на:**
- ✅ Fedora 44
- ⏳ openSUSE (не тестировалось, возможно AppArmor)

### Пакетный менеджер через detector

**Проблема:** Инсталлятор должен работать на разных дистрибутивах  
**Решение:** Единый метод `detector.detect_os()` возвращает пакетный менеджер  
**Реализация:**
```python
detection["os"]["pkg_manager"]  # "pacman", "dnf", "apt", "zypper", "emerge", "xbps"
```
- Все шаги используют этот метод для определения команды установки
- Маппинг команд в `requirements.py`:
  ```python
  PACKAGE_MANAGERS = {
      "pacman": ["sudo", "pacman", "-S", "--noconfirm"],
      "dnf": ["sudo", "dnf", "install", "-y"],
      "apt": ["sudo", "apt-get", "install", "-y"],
      "zypper": ["sudo", "zypper", "install", "-y"],
      ...
  }
  ```

- `hf-mirror.com` — китайское зеркало HuggingFace

- `pip install hf_transfer`
