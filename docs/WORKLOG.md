#### Архитектура ветвления диалога (в процессе реализации)

**Концептуальные решения:**
- **Файловая архитектура**: Каждый чат = папка в `data/ollama/chats/{название_чата}/`
  - `main.json` — последняя активная последовательность + словарь `branches`
  - `branch_YYYY-MM-DD_HH-MM.json` — ветки (техническое имя)
  - Пользователь выбирает папку, а не файл
  - Прозрачность: все ветки видны в файловом менеджере

- **Стабильные индексы**: Каждое сообщение пользователя получает `user_msg_index` (как ID в БД)
  - При обрезке индексы не пересчитываются
  - Ветки привязываются к конкретному `user_msg_index`
  - Обратная совместимость: старые чаты автоматически получают индексы при загрузке

- **Кнопки под сообщениями пользователя** (по аналогии со статистикой под ответами модели):
  - **✂️ Обрезать** — удаляет всё после этого сообщения
  - **🌿 Ответвиться** — создаёт ветку от этого сообщения
  - **📂 N** — счётчик веток от этого узла (клик открывает список альтернатив)

**Реализовано:**
1. **Структура JSON (`core/chat_manager.py`)**:
   - Добавлен `_user_msg_counter` и автоматическая нумерация `user_msg_index`
   - Обратная совместимость: при загрузке старых чатов индексы назначаются автоматически

2. **Экспорт в папки (`core/chat_exporter.py`)**:
   - Метод `export_chat()` принимает `chat_folder_name`, `is_branch`, `parent_user_msg_index`
   - Создаёт папку с санитизированным именем чата
   - При `is_branch=True` создаёт `branch_*.json` и обновляет `main.json` (добавляет ветку в словарь `branches`)

3. **UI кнопок (`core/markdown_parser.py`, `ui/chat_widget.py`)**:
   - `render_user_message()` теперь принимает `user_msg_index` и `branches_count`
   - Рендерит кнопки ✂️ / 🌿 / 📂 под сообщением пользователя
   - Добавлены сигналы `trim_requested`, `branch_requested`, `switch_branch_requested`

4. **Логика обрезки и ветвления (`ui/tabs/ollama_tab.py`)**:
   - Методы `_on_trim_requested()`, `_on_branch_requested()`, `_on_switch_branch_requested()`
   - Флаги `_is_branching` и `_branch_from_index` для отслеживания режима ветвления
   - При сохранении в режиме ветвления создаётся `branch_*.json` и обновляется `main.json`

**Не завершено:**

## Сессия 2026-08-23: Теоретическое планирование архитектуры

### Обсуждаемые темы

1. **Архитектура сохранения чатов**:
   - Утверждён гибридный формат: JSON (для машины/RAG, точное воспроизведение) + TXT (для человека, markdown с разделителями).
   - Две галочки в настройках (вкладка "Чат"): можно отключить любой формат.
   - Автосохранение после каждого сообщения + кнопка "💾 Сохранить" для экспорта.

2. **Управление контекстом LLM**:
   - Обсуждён `ContextTracker` для приближённого подсчёта токенов (символы × коэффициент).
   - Индикатор в статусбаре: "45K / 128K токенов (35%)" с цветовой индикацией.
   - Предупреждения при переполнении (>90% контекста).

3. **Перевод промптов для Diffusers**:
   - Выявлена возможность использования сверхлёгких LLM (`qwen2.5:1.5b`) для мгновенного перевода визуальных промптов.
   - Контекст мизерный (физика, материалы, освещение) — маленькие модели справляются отлично.
   - Кнопка "🌐 Перевести промпт" в DiffusersTab — будущая фича.

4. **Ollama Image Generation (анализ)**:
   - **Идея**: Добавить "Express-режим" генерации изображений через нативный API Ollama (модели `x/flux2-klein`, `x/z-image-turbo`) как лёгкую альтернативу тяжёлому стеку Diffusers.
   - **Статус**: ⏸️ **Отложено (Backlog)**.
   - **Причина**: На текущий момент (январь 2026) экспериментальная поддержка генерации изображений в Ollama доступна **только на macOS**. Linux-поддержка ожидается в будущих релизах.
   - **Архитектурные заметки на будущее**:
     - Не заменять текущий `DiffusersTab`, а добавить переключатель режимов (Express/Pro).
     - Express-режим будет использовать `ollama_client.py`, не требует `torch`/`diffusers`, но **не поддерживает** чекпоинты, resume, ControlNet и тонкую настройку scheduler (black box).
     - Потребление RAM: ~4-6 ГБ (для 4B моделей), что хорошо для слабых машин, но требует контроля в `resource_manager.py`.

### Архитектурные решения

- **Гибридный формат хранения чатов**: JSON (структура, метаданные, для RAG) + TXT (человекочитаемый markdown, для архива). Затраты пространства мизерные (~230 KB на чат из 100 сообщений).
- **Express vs Pro режимы**: Ollama Image Gen — это "мыльница" (простота, экономия RAM), Diffusers — "зеркальная камера" (контроль, чекпоинты, resume). Они дополняют, а не заменяют друг друга.
- **Контекстный трекер**: Приближённый подсчёт токенов (символы ÷ 4 для английского, ÷ 2 для русского) достаточно для UI. Точный подсчёт через токенизатор — overkill.

### Отложенные задачи (Backlog)

- **Ollama Image Gen (Express-режим)**: Интеграция нативной генерации изображений через Ollama. *Статус: отложено до официального выхода Linux-поддержки в Ollama.*
- **Быстрый перевод промптов**: Использование лёгкой LLM (1.5B) для мгновенного перевода русских визуальных промптов в оптимизированный английский формат для CLIP.

## Сессия 2026-08-23 (дополнение): Анализ OllamaDiffuser

### Найденный проект
- **OllamaDiffuser** (LocalKinAI/ollamadiffuser) — сторонняя Python-библиотека, имитирующая UX Ollama для генерации изображений
- **Сайт**: https://www.ollamadiffuser.com/
- **GitHub**: https://github.com/LocalKinAI/ollamadiffuser
- **Версия**: v2.0.17 (май 2026)
- **Установка**: `pip install "ollamadiffuser[gguf]"` (для Linux с поддержкой квантованных моделей)

### Ключевые особенности
1. **Реестр 60+ моделей** (FLUX.1, FLUX.2 Klein, SANA, SD 3.5, Z-Image и др.) с метаданными (VRAM, шаги, лицензия)
2. **Поддержка GGUF** — квантование для запуска на слабом железе (3-8 GB VRAM вместо 20+ GB)
3. **MLX Backend** для Apple Silicon (2-3× быстрее PyTorch+MPS)
4. **Стратегия Lazy Loading** — препроцессоры грузятся только при первом запросе
5. **Python API**: `from ollamadiffuser.core.models.manager import model_manager`
6. **MCP сервер** — интеграция с AI-ассистентами (Claude Code, Cursor)

### Архитектурное решение
- **Express-режим** (будущая фича LocalAILite) будет использовать `ollamadiffuser` как альтернативный движок
- **Pro-режим** (текущий `scripts/generate_diffusers.py`) остаётся для задач с чекпоинтами, resume и полным контролем
- **Переключатель режимов** будет добавлен в `ui/tabs/diffusers_settings_panel.py` (радиокнопки Pro/Express)
- **Расширение `core/models_registry.py`** — добавление флага `engine: "express"` для моделей из реестра OllamaDiffuser

### Важные уточнения
- Это **не** экспериментальная фича официального Ollama (которая пока только на macOS)
- Это **сторонняя библиотека**, которая работает на Linux/Windows через GGUF и оптимизированные diffusers
- Интеграция возможна **прямо сейчас**, не требует ожидания релизов от разработчиков Ollama

### Влияние на текущие приоритеты
- **Не меняет** последовательность задач из HANDOFF.md (восстановление UI, ветвление, загрузка файлов)
- Относится к **Этапу 3 (Оптимизация и расширение)** — после закрытия приоритетных задач v1.6.0
- Зафиксировано как утверждённая стратегия для будущего спринта по Express-режиму
